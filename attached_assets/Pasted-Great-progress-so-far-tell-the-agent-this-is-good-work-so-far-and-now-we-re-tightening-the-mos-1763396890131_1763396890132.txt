## 3. Technical Integration Instructions

### 3.1 Data Structures Needed

In the frontend global state (store / context):

* `currentUser`:

  * `id`
  * `displayName` (e.g. “Vital”)
  * `role` = “Chairman”

* `currentCompanyId` (nullable):

  * `null` = no specific company selected (Assistant acts at group level).
  * Or set to a company’s id.

* `chairmanChatHistory`: array of messages:

  * `[{ sender: 'user' | 'assistant', content: string, timestamp: ... }]`

In the backend:

* A **Chairman Assistant chat endpoint**, for example:

  * `POST /api/chat/chairman-assistant`
  * Body:

    * `userId`
    * `message`
    * `currentCompanyId` (optional)
* This endpoint calls the existing chat/orchestrator module, with:

  * System prompt that says:

    * “You are the Chairman Assistant. User name is X. Current company context is Y (or none). Act as strategic assistant and orchestrator of companies and agents.”

### 3.2 Reuse Existing Chat Module

**Do NOT build a separate prototype chat.**

Instead:

1. Identify the current chat component used elsewhere (e.g. for other agents).
2. Wrap it as a `ChatDock` component with:

   * Props:

     * `conversationId` or `mode: 'chairman-assistant'`
     * `currentCompanyId`
     * `user` (Chairman).
3. On homepage:

   * Render `<ChatDock mode="chairman-assistant" ... />` in the bottom dock.
4. Ensure the chat sends requests to the correct backend endpoint (`chairman-assistant` mode).

## 4. Behavior of the Chairman Assistant (Logic)

The backend LLM prompt for the Chairman Assistant must:

* Always receive:

  * `user.name`
  * `user.role`
  * `currentCompany` (id + basic info if set)
  * High-level group metrics (if available)

* Must:

  * Address the user by name (e.g. “Vital,”).
  * Understand the difference between:

    * No company context (talk at group level),
    * Specific company context (only talk about that company).

Examples of behavior:

* User: “What should we focus on today?”

  * Assistant checks metrics for current company (if set) or all companies.

* User (on homepage with Company X selected):
  “Increase meetings in Abidjan this month.”

  * Assistant:

    * Understands this refers to Company X,
    * Suggests actions OR can send instructions to specific agents (Sales/Outreach) in the backend.

## 5. State & Context Passing

### 5.1 Frontend → Backend

When user sends a message:

```json
{
  "userId": "USER_123",
  "message": "I want to get more meetings in Abidjan next week.",
  "currentCompanyId": "COMPANY_456"
}
```

Backend:

* Loads:

  * User profile,
  * Company basic info (if `currentCompanyId`),
  * Relevant metrics.

* Builds LLM context like:

> “User Vital (Chairman) is asking: ‘I want to get more meetings in Abidjan next week.’
> Current context: Company Exportunity CI (id COMPANY_456), sector: trade/logistics, market: Abidjan.
> Your role: Chairman Assistant. Explain clearly, propose a plan, and optionally suggest which internal agents to activate.”

### 5.2 LLM Response → UI

* Response text is returned and appended to `chairmanChatHistory`.
* Optionally, the response can include **structured actions** later (e.g. propose to create a campaign), but for now just text is enough.
