## 1. Goal for the Agent Hierarchy

> **Make the Agent Hierarchy look and behave like a real org chart tree, grouped by departments, simple to understand at a glance.**

Right now it’s messy and flat/confusing. We want:

* A **tree**, not a list.
* Clear **departments** (Marketing, Sales, Finance, Legal, Operations, etc.).
* Within each department, a tree of **agents** with parent/child (manager → sub-agent).
* Fully integrated with the **Chairman’s Assistant** so it can read and modify this tree.

---

## 2. Data Model Changes

### 2.1 Add Departments

In the backend:

* Introduce a `Department` entity for each company:

```ts
type Department = {
  id: string;
  companyId: string;
  name: string;        // e.g. "Sales", "Marketing", "Finance", "Legal", "Operations"
  color?: string;      // optional, for UI color-coding
  order?: number;      // for display ordering
};
```

### 2.2 Extend Agent Model

Each agent must now belong to a department and a parent in the tree:

```ts
type Agent = {
  id: string;
  companyId: string;
  name: string;
  roleTitle: string;
  departmentId: string;      // link to Department
  parentAgentId?: string;    // null if top of that tree (e.g. Head of Sales)
  isDepartmentHead?: boolean;
  // other fields: personality, KPIs, permissions, etc.
};
```

This gives us:

* Department → Agent(s) → Sub-agents → etc.

## 3. UI: Tree-Based Agent Hierarchy

### 3.1 Where

This is the **Agents & Hierarchy** page inside each **Company Workspace**.

### 3.2 Layout

Split the page into two main areas:

1. **Left: Tree View (Org Chart)**
2. **Right: Details Panel (Agent / Department info)**

#### Left: Tree View

* Show **departments as the top-level nodes**.
* Under each department, show agents in a **tree structure**:

Example (textual):

* Company CEO Orchestrator

  * Sales Department

    * Head of Sales (Agent)

      * SDR Agent – French West Africa
      * SDR Agent – English West Africa
  * Marketing Department

    * Head of Marketing

      * Email Campaign Agent
      * Social Media Agent
  * Finance Department

    * Finance Controller Agent

      * Tax Agent – Côte d’Ivoire
      * Tax Agent – UAE

Visual behavior:

* Each **department** is a big collapsible node:

  * Click to expand/collapse that department.
* Each **agent node**:

  * Shows name + role + small status icon (Active/Paused).
* Child agents appear **indented or branching** visually (like a real tree).
* Lines connecting parent ↔ child.

### 3.3 Interactions

* **Click department**:

  * Highlights all agents in that department.
  * Shows Department Details in the right panel.

* **Click agent**:

  * Highlights that node.
  * Opens Agent Profile in the right panel.

* **Expand/Collapse**:

  * Allow collapsing each department and subtrees for readability.

* **Drag & Drop (later or now if possible)**:

  * Drag an agent to:

    * Another parent agent (change `parentAgentId`),
    * Another department (change `departmentId`).
  * Confirm with a tiny popup:

    > “Move [Agent] under [New Parent] in [Department]?”

* **Filter / Search**:

  * Small search box at top:

    * Filter by name, role, department.
  * Optionally show only:

    * “Department Heads”,
    * “Active agents”,
    * “Paused agents”.

## 5. Integration with the Chairman’s Assistant

The **Chairman’s Assistant** must:

1. **Understand this tree structure** (departments + agents).
2. **Be able to modify it via chat instructions**.

Examples:

* “Create a new Marketing Department for Dubai.”
  → TA creates a new Department, suggests initial agents.

* “Create a French-speaking Sales agent under Head of Sales in Abidjan company.”
  → TA:

  * Finds Sales Department,
  * Finds Head of Sales,
  * Proposes a new agent profile,
  * On approval, creates agent with `departmentId` = Sales, `parentAgentId` = Head of Sales.

* “Move the Tax Agent from Finance to Legal.”
  → TA:

  * Updates agent’s `departmentId`,
  * Keeps or adjusts tree.

* “Pause all Marketing agents for Company X.”
  → TA:

  * Finds all agents in Marketing department,
  * Sets them Paused.

The Assistant must be aware of:

* which departments exist,
* who is head of each,
* how many agents per department.
