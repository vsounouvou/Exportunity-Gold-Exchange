## 3. Knowledge Base Page (ex-Memory)

You were very clear on the distinction:

* **Agent Memory** = internal, per-agent experience / context it builds over time.
* **Knowledge Base** = documents and data **the user or AIs add** (files, web imports, AI-written docs, etc.), shared as a resource across agents.

So we design Knowledge Base as a **content hub** for the company.

### 3.1 Key Concepts

* **Knowledge Base = shared, structured repository** per company.
* Includes:

  * Uploaded docs (PDF, Word, Excel, images…),
  * Notes / internal docs,
  * AI-generated reports, summaries, SOPs,
  * Web imports (pages you capture),
  * Folder / space organization.

Agents access it via Actions:

* `kb_add_document`
* `kb_search`
* `kb_get_document`
* `kb_tag_document`
* etc.

Agent Memory (per agent) remains **separate** and is not user-visible on this page (it’s more for internal behavior).

---

### 3.2 Knowledge Base Page – Layout

At the top:

* Title: **Knowledge Base**
* Company selector: `All Companies` / `[Company X]`
* Big primary button: `+ Add to Knowledge Base`
* Search bar: `Search across documents, titles, and content…`

Below, use tabs:

* `Documents`
* `Spaces / Collections`
* `Sources` (integrations)
* (Later) `AI Drafts` or `Generated Docs`

---

### 3.3 `+ Add to Knowledge Base` Flow

When the user clicks the button, show options:

1. **Upload file**

   * PDF, Word, Excel, images, etc.

2. **Paste text / Create note**

   * Opens a rich text editor for internal notes, SOPs, strategies.

3. **Import from URL**

   * Capture content from a public web page (with summarization and cleaning).

4. **Create with AI**

   * Let the Chairman’s Assistant generate a structured doc:

     * e.g. “Company Profile,” “Sales Playbook for Côte d’Ivoire,” “Gold Export SOP.”

For each added item, prompt:

* Title
* Description
* Company (if you’re in All Companies mode)
* Tags (Sales, Finance, Gold, Compliance, etc.)
* Assign to **Space/Collection** (e.g. “Sales Playbook”, “Legal”, “Gold Trade Docs”)

Behind the scenes, each document is indexed for semantic search.

---

### 3.4 Tab: **Documents**

A table/grid of all docs in the selected company:

Columns:

* Title
* Type (`PDF`, `Note`, `AI Doc`, `Web Import`)
* Company
* Space / Collection
* Tags
* Last updated
* Created by (Human or Agent)

Filters:

* By type (file, note, AI doc, web)
* By tags
* By space/collection
* By date

Click a document:

* Open a **Document Detail** view:

  * Preview / viewer (for PDF/Note/AI doc).
  * Metadata:

    * Company
    * Space
    * Tags
    * Author (human/agent)
  * Actions:

    * `Open in full`
    * `Download`
    * `Edit` (for notes/AI docs)
    * `Retag`
    * `Summarize with AI`
    * `Create derivative` (e.g. email template, social post)

Agents get access via actions like:

* `kb_search(query, companyId, tags?)`
* `kb_get_document(documentId)`

### 3.7 Interaction with Agents and Memory

We must keep the distinction very clear in the architecture:

1. **Knowledge Base = shared, curated corpus**

   * Agents read from it using `kb_search`.
   * Agents can write to it via:

     * `kb_add_document` (e.g. after summarizing a meeting, they store “Weekly Report”).
   * When the Chairman asks:

     > “Create a playbook for new sales agents and store it in our Knowledge Base.”

     * Chairman’s Assistant:

       * Generates doc,
       * Calls `kb_add_document`,
       * Assigns it to `Sales Playbooks` space.

2. **Agent Memory = private, internal long-term memory**

   * Stored separately per agent:

     * Preferences,
     * Patterns,
     * Frequent contacts,
     * Personal style.
   * Not edited from Knowledge Base page.
   * Managed via memory Actions (`memory_create`, `memory_search`) that are **per agent**.

So, **Knowledge Base page** is about what *the company knows*,
while **Agent memory** is about what each agent “remembers”.
