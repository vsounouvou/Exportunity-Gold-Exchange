> **Feedback:**

>

> * The assistant **remembers the past**, but the UI is organized **by day**.

Key rules:

1. **Chats are associated with calendar days**, not with arbitrary sessions.
2. A **new day = a new chat segment** (for that day).
3. If there was **no conversation on a given day**, there is **no chat entry** for that day.
4. The assistant **still keeps long-term memory and context**, even though the UI is segmented by date.

## 2. Data Model: Day-Based Chats

Introduce a `ChatDay` concept:

```ts
type ChatDay = {
  id: string;
  userId: string;
  date: string; // e.g. "2025-11-17"
  messages: ChatMessage[];
  companyId?: string | null; // optional, if context is company-specific
};

type ChatMessage = {
  id: string;
  sender: 'user' | 'assistant';
  content: string;
  timestamp: string; // full time
};
```

Behavior:

* When the Chairman sends the **first message of the day**:

  * If there is no `ChatDay` for today yet → **create one**.
* All messages for that date are appended into **that day’s `ChatDay.messages`**.
* No messages → no `ChatDay` record.

## 5. Memory & Context Across Days

Very important part:
Even though the UI is **per day**, the assistant must still:

* **Remember old information**,
* Reuse important context in new conversations,
* Decide what to store in its own memory.

### 5.1 Daily Summary & Memory Engine

Implement a **Daily Summary** layer:

For each `ChatDay`:

* After a conversation (e.g. at day end, or after inactivity), the system:

  * Generates a **summary** of important points:

    * Decisions,
    * New preferences,
    * Company changes,
    * New objectives,
    * Anything stable and reusable.
  * Writes this into a `Memory` object separate from raw messages.

```ts
type DailySummary = {
  chatDayId: string;
  date: string;
  summaryText: string;
  extractedFacts: MemoryFact[];
};

type MemoryFact = {
  type: 'preference' | 'goal' | 'company_update' | 'agent_update' | ...;
  content: string;
  importance: 'low' | 'medium' | 'high';
};
```

Only **MemoryFacts** are used as **long-term context**.

### 5.2 Context on a New Day

When a **new day starts** and the Chairman sends the first message:

* The backend:

  * Loads:

    * Today’s `ChatDay` (new or existing),
    * The last N **DailySummaries** (e.g. last 7 days or last X important facts),
    * The stable **Chairman Profile** & **Instance Profile** (BS Detail).

LLM context for the Chairman’s Assistant includes:

* Short summary of recent days,
* Long-term facts (goals, preferences, key decisions),
* The new message.

So the assistant can say:

> “Good morning, Chairman. Last time we decided to focus on the Abidjan sales pipeline and create a new outreach agent. I can update you on progress or we can define this week’s priorities.”

**Even though** the UI is “new chat for today”, the **brain remembers everything important.**

## 6. Daily Flow Example

**Day 1:**

* User opens platform → sends “Hey”.
* System:

  * Creates `ChatDay` for 2025-11-17.
* Assistant:

  * Onboards company, agents, etc.
* End of day:

  * System summarizes:

    * “Created Company X in Côte d’Ivoire, focus on trade.”

    * “Chairman prefers concise answers.”

**Day 5:**

* User returns → first message: “Good morning.”
* System:

  * Creates `ChatDay` for 2025-11-21.
  * Loads last 7 days summaries.
* Assistant:

  * “Good morning, Chairman. Since we last spoke, your sales agent has booked 3 meetings for Company X. Do you want a quick status review or should we define this week’s goals?”

The Chairman can scroll up and collapse/un-collapse each day, and if he wants a very precise memory, he goes to **Diary → select date**.
