# ✅ **SPECIFICATION: SUPPLIER SYSTEM + MARKETPLACE + SELLER/DELIVERY/FRANCHISEE DEMO ACCESS**

## **1. Supplier Philosophy (Core Rule)**

* The platform only accepts **producers** — people and companies that **make what they sell**.
* **No resellers. No middlemen. No dropshipping.**
* Objective: map every country, region, city, neighborhood with **verified local producers**.

---

## **2. Global → Africa-First Strategy**

* Tier 1 rollout: **Black Africa / Sub-Saharan Africa**.
* Tier 2: Africa at large.
* Tier 3: rest of the world.
* Architecture must support global onboarding from day one.

---

## **3. Marketplace Structure**

### **3.1. Entities**

1. **Shops / Sellers (Producers)**
2. **Products**
3. **Delivery Agents**
4. **Buyers**
5. **Admin**
6. **Shareholders**
7. **Franchisees**

### **3.2. Hierarchy**

* A **Seller** owns Products.
* Products belong to **one precise Geolocation node**.
* A **Delivery Agent** operates inside a limited radius.
* A **Franchisee** owns a geographic territory.
* Platform Admin can override, audit, suspend, view KPIs.

---

## **4. Precise Geolocation System**

The marketplace must map:

* **Continent → Country → Region → City → District → Neighborhood → Street → Exact GPS point**

Every **seller**, every **delivery agent**, every **product** is tied to:

* A **GPS coordinate**, AND
* A **geographical hierarchy node**

### Buyer Experience (Core Rule)

When a buyer searches a product:

1. System identifies buyer GPS.
2. System retrieves closest sellers that produce that item.
3. Products appear on a **muted map**, with **powerful colored category icons** (navy-blue theme UI).
4. Buyer can:

   * order,
   * pick up,
   * or request delivery.

---

## **5. Seller Requirements**

### A seller must:

1. **Produce what they sell.**
2. Have a **physical location**.
3. Provide **inventory** (text + prices + optional photos).
4. Accept the platform’s **payment gateway integration**.

### Seller Account Features

* Add/Edit/Delete products
* Manage stock
* Set opening hours
* Receive and process orders
* Chat with the buyer
* Financial dashboard (wallet + withdrawals)
* Sales analytics

---

## **6. Financial Architecture**

The platform acts like a **payment gateway**:

* Every buyer must load money into a **wallet** (top-up via bank card, mobile money, etc.).
* Payments are done using **vouchers / wallet credits**.
* Sellers and agents receive funds in real time.

This aligns with your **broker strategy** described in your Harvard paper.

  * commissions + royalties
  * performance dashboard

When buyers browse:

* They see **the closest producers**.
* Payment is **wallet-based**.
